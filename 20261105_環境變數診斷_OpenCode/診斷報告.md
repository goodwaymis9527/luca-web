# 診斷報告

## 1. 錯誤現象

```text
⨯ Error: DATABASE_URL 沒有設定。請檢查 .env.local 或 Vercel 專案的環境變數
    at getPool (lib\db.js:12:11)
    at listItems (lib\db.js:42:19)
    at Page (app\page.jsx:7:32)
```

路徑是 Windows 反斜線、且前面有 `Compiling / ...`，所以這是**本機 `next dev`**，不是 Vercel 執行時；但同一個根因在線上也會爆發。

## 2. 根因

`lib/db.js` 的邏輯本身沒有問題（延遲建立池、參數化 SQL、`max: 3` + `idleTimeoutMillis` 都是 serverless 的正確做法）。真正的問題是**秘密值不存在於任何一側**：

| 位置 | 實際狀態 | 檢查方式 |
|---|---|---|
| 本機 `D:\LucaWebVercel` | 只有 `.env.example`（佔位 `postgresql://CHANGE_ME`），**沒有 `.env.local`** | `Get-ChildItem -Force -Filter ".env*"` |
| Vercel `goodwaymis-2968/luca-web-vercel` | **No Environment Variables found**（production/development 皆空） | `npx vercel env ls` |

關鍵：Next.js 在開發模式只讀 `.env` / `.env.local`，**`.env.example` 永遠不會被讀取**。因此 `process.env.DATABASE_URL` 是 `undefined`，`getPool()` 在第一次被呼叫時（`page.jsx:7` 的 `listItems`）throw。

另一個需要釐清的點：CLI 登入的帳號是 `goodwaymis-2968`，而倉庫屬於 `goodwaymis9527`。如果你在 Vercel 儀表板看到的變數是在**另一個專案或團隊**下，`vercel env pull` 就不會看到它。

## 3. 線上實測（deployment `dpl_7kMYveLyKraJ3tw9FzZ7FCsZReZ8`）

`vercel inspect` 顯示 status Ready、build 25s 成功——**build 成功不等於能跑**，因為 `lib/db.js` 刻意不在 module load 時 throw，錯誤只在請求時發生。

`vercel logs` 抓到 production 執行期日誌：

```json
{"level":"error","environment":"production","runtime":"nodejs26.x","requestPath":"/",
 "message":"Error: DATABASE_URL 沒有設定...","digest":"696391097"}
```

所以本機與 production **同一個根因**，兩邊都要補變數。

補一點：直接打 `https://luca-web-vercel-cvtcarbzh-goodwaymis-2968.vercel.app/api/health` 會拿到 Vercel 登入頁（Deployment Protection 開啟），外部 `curl` 驗證要關保護或帶 `Authorization: Bearer <token>`，otherwise 用 `vercel logs` 看。

## 4. 處置步驟

1. 取得 Neon（或 Supabase）的 connection string。
2. 寫入 Vercel 兩個環境：
   ```powershell
   npx vercel env add DATABASE_URL production
   npx vercel env add DATABASE_URL development
   ```
3. 拉回本地產生 `.env.local`：
   ```powershell
   npx vercel env pull
   npm run dev
   ```
4. 上線驗證：
   ```powershell
   npx vercel --prod
   curl https://luca-web-vercel.vercel.app/api/health
   ```
   預期 `{"ok":true,"db":"connected"}`。

## 5. 三個容易踩的坑

- **`.env.local` 不會被 `.vercel env pull` 之外的工具產生**：它被 `.gitignore` 排除，換機器或重新 clone 後一定要重新 pull。
- **`page.jsx` 有 `force-dynamic`**，所以錯誤只會在使用者請求時出現，`next build` 不會先炸——這是 `lib/db.js` 刻意延遲 throw 的結果，屬正常設計。
- **`ssl` 判斷依賴字串裡的 `sslmode=require`**。Neon 的字串通常自帶；但若你用的是 Supabase 的 pooler 或透過 pgbouncer，字串可能沒有 `sslmode`，此時 `ssl: false` 會被 Neon 拒連線（`SSL required`）。較穩健的寫法是預設 `ssl: { rejectUnauthorized: false }`，只有明確寫 `sslmode=disable` 才關掉。此項**尚未改動原始檔**，等你確認再改。

## 6. 思考紀錄

- 先判斷「是程式 bug 還是設定缺失」：錯誤訊息已經指向環境變數，但仍實際查了檔案與 `vercel env ls` 兩邊，避免只照字面猜測。
- 交叉比對時發現「使用者認為 Vercel 上有變數」與 CLI 實際輸出矛盾，因此把帳號/專案不一致寫進報告，這是本次最可能誤會來源。
- 未擅自寫入 `.env.local`：內容是秘密值，且需要真實字串才有意义。
